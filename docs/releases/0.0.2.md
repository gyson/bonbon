BonBon 0.0.2 adds saved projects, tool presets, managed Git worktrees, and multiple
durable session drafts. You can archive finished work, resize the message editor, and
upgrade from v0.0.1 without losing recorded history.

## Included

- Organize sessions under saved projects or the built-in General project. Removing a
  project preserves its sessions, history, files, and running processes.
- Create several drafts per project. Each keeps its name, launch choices, message, and
  attachments across view changes and server restarts. Starting keeps the same session
  ID and leaves the message ready for an explicit Send.
- Define named, single-line startup commands in Settings. New sessions start an
  interactive shell and submit the selected command once. Reconnecting never submits it
  again.
- Optionally start in a managed Git worktree from a selected branch or commit. BonBon
  copies only committed files. It does not copy local changes, ignored files, or
  dependencies. Stopping a session preserves the worktree. Removal rejects active or
  dirty worktrees. It keeps their branches and recorded history.
- Archive drafts and finished sessions, then find and restore them through Archived.
  Search matches names, IDs, and folders before pagination. Restoration starts no
  process, and archiving deletes no history or files.
- Drag the divider between the terminal and message editor, or resize it with the
  keyboard. Its size stays with the browser view across session switches.
- Terminal activity sets the session order. View changes, draft saves, and reconnects at
  the same size no longer move a session up the list. They do not request an unnecessary
  redraw.
- Quit BonBon in the menu bar remains tied to its original server, even if its
  connection file is missing or replaced.

## Upgrade from v0.0.1

```sh
bonbon update
```

The update replaces the executable while existing servers and sessions continue. When
ready, run:

```sh
bonbon server restart
bonbon ui
```

Restart ends active sessions. The new server upgrades the database before it accepts
requests. Then reopen the UI at its new URL.

SQLite formats 3 (v0.0.1), 4, and 5 upgrade automatically to format 6 using SQL
migrations embedded in the executable. The upgrade preserves history, original bytes,
stable IDs, event sequences, drafts, attachments, settings, and project and worktree
metadata. Existing v0.0.1 sessions remain standalone with their recorded workspace
paths. All pending migrations commit in one transaction.

A failed migration rolls back and stops startup. Unsupported and newer formats are
rejected without changing their contents. Database downgrades are not supported.

## Install

Install with one command:

```sh
curl -fsSL https://github.com/gyson/bonbon/releases/latest/download/install.sh | sh
```

The installer selects Apple Silicon or Intel. It verifies SHA-256 and the executable
version. It installs to `~/.local/bin`. If needed, add that directory to PATH. Use
installer `--version 0.0.2` to select this release explicitly. Then run
`bonbon server start` and `bonbon ui`.

## Scope and limits

- macOS Apple Silicon and Intel archives, plus `install.sh` and `checksums.txt`.
  Installed binaries need neither Go, Node.js, nor GitHub CLI.
- Built with Go 1.27.1 and `CGO_ENABLED=0`. Archives and the standalone executable
  include the project license and dependency notices.
- Production data remains in `~/.bonbon`, separate from `~/.bonbon-dev`. This release
  uses SQLite format 6 and protocol `bonbon/15`.
- Git worktrees require an existing commit and do not support submodules. Worktree files
  and other workspace contents remain outside SQLite.
- Native agent resume, conversation forks, imports, and backup/restore remain
  unavailable. Terminal recordings do not restore a process or hidden model state.
- Linux and Windows packages, background updates, and Apple Developer ID
  signing/notarization are not included.

## Validation

- Local checks: `make test`, `make check`, `make web-check`, and `go test -race ./...`.
- Frozen database fixtures cover formats 3–6, record preservation, rollback, repeated
  and concurrent opens, and unsupported-format rejection. Server subprocess tests cover
  startup upgrades and interruption recovery without replaying input.
- Shell and WebSocket fixtures cover projects, independent drafts, tool commands,
  worktree creation/removal, archiving, and session lifecycle. Frontend fixtures cover
  connection handling, rendered frames, composition, and project helpers.
- A compiled release smoke check uses a temporary instance to verify version reporting,
  the embedded UI and license notices, read-only SQL, and clean shutdown.
- Publication requires tests and native release smoke checks on both Apple Silicon and
  Intel runners. These checks use synthetic shells. This release does not claim a new
  end-to-end run with a real agent CLI.
