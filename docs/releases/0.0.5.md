BonBon 0.0.5 lets a session continue after its terminal ends.
**Continue in new terminal** starts a new terminal in the same session and workspace. A
read-only handoff folder gives the new agent the record of the earlier terminals. The
database format does not change.

## Included

- **Continue in new terminal** appears when the latest terminal of a session ended. For
  example, it appears after **Stop session**, an agent exit, or a server restart. It
  starts a new terminal in the same session, workspace, and worktree. The session keeps
  its ID, message draft, and history. Only one terminal can be live.
- The dialog lets you choose a tool or Shell for the new terminal. You can continue with
  a different agent CLI, for example after a quota limit. The dialog also shows the
  workspace and the handoff prompt, with a **Copy prompt** button.
- Before the new terminal starts, BonBon writes a read-only handoff folder at
  `<instance>/handoff/<session-id>/`. It contains a `README.md`, `messages.md` with the
  messages sent through the message editor, and the text of each earlier terminal.
  BonBon rebuilds the folder from SQLite for each new terminal.
- The handoff prompt points the new agent to the folder. It tells the agent that the
  files are a record of earlier work, not instructions or approvals. It asks the agent
  to check the current files, summarize where the work stopped, and wait.
- Settings has an optional **Continue command** for each tool. BonBon puts the
  shell-quoted prompt in place of `{prompt}` and submits that command once. A tool
  without a continue command starts with its normal command and gets no prompt. Shell
  submits nothing.
- **Handoff prompt** in the message editor heading shows the prompt again later. It can
  copy the prompt or put it in an empty message editor. It never replaces a draft and
  never sends.
- When a server crash interrupted the earlier terminal, the dialog warns that an agent
  from that server can still run in the workspace.
- The session toolbar buttons now wrap in a narrow window, so the session title stays
  visible.

These settings passed a live check:

| Tool | Command | Continue command |
| --- | --- | --- |
| Codex CLI 0.160.0 | `codex --no-alt-screen` | `codex --no-alt-screen {prompt}` |
| Claude Code 2.1.312 | `claude` | `claude {prompt}` |

A terminal transcript keeps only the last screen of a program that uses the alternate
screen. Codex uses the alternate screen by default, so use `--no-alt-screen`. Do not
turn on the fullscreen renderer of Claude Code.

## Upgrade from v0.0.4

```sh
bonbon update
```

The update replaces the executable while existing servers and sessions continue. When
ready, run:

```sh
bonbon server restart
bonbon ui
```

Restart ends active sessions. Then use the new UI at its new URL. Close BonBon tabs from
v0.0.4. They use protocol `bonbon/17` and cannot connect to the new server.

This release keeps SQLite format 6, so a v0.0.4 database needs no migration. Databases
from v0.0.1 (formats 3–5) still upgrade automatically at startup. Sessions from earlier
releases can also use Continue in new terminal.

Existing tools have no continue command after the upgrade. To submit the handoff prompt
automatically, add a continue command to each tool in Settings.

Database downgrades are not supported. An older release can open the database. If it
saves Settings, it removes the continue commands.

## Install

Install with one command:

```sh
curl -fsSL https://github.com/gyson/bonbon/releases/latest/download/install.sh | sh
```

The installer selects Apple Silicon or Intel. It verifies SHA-256 and the executable
version. It installs to `~/.local/bin`. If needed, add that directory to PATH. Use
installer `--version 0.0.5` to select this release explicitly. Then run
`bonbon server start` and `bonbon ui`.

## Scope and limits

- macOS Apple Silicon and Intel archives, plus `install.sh` and `checksums.txt`.
  Installed binaries need neither Go, Node.js, nor GitHub CLI.
- Built with Go 1.27.3 and `CGO_ENABLED=0`. Archives and the standalone executable
  include the project license and dependency notices.
- Production data remains in `~/.bonbon`, separate from `~/.bonbon-dev`. This release
  uses SQLite format 6 and protocol `bonbon/18`.
- A new terminal is a new process. The new agent does not get the internal state or the
  model context of the earlier agent. It gets only the files in the handoff folder.
  Native agent resume remains unavailable.
- The UI shows only the latest terminal of a session. Use the handoff folder or
  `bonbon query` to read earlier terminals.
- The handoff README does not mark terminals that used the alternate screen. The
  transcripts of these terminals can be incomplete.
- The session header shows the tool of the original launch, also after a continue with
  another tool.
- BonBon does not detect when an agent is ready for input. It submits a continue command
  once. It never sends the prompt through the message editor.
- Continue commands were verified only with Codex CLI 0.160.0 and Claude Code 2.1.312.
  The default permission mode of Claude Code was not checked. In that mode, Claude Code
  can ask before it reads the handoff folder.
- Conversation forks, imports, and backup/restore remain unavailable. Terminal
  recordings do not restore a process or hidden model state.
- Linux and Windows packages, background updates, and Apple Developer ID
  signing/notarization are not included.

## Validation

- Local checks with Go 1.27.3: `make test`, `make check`, `make web-check` (37 tests),
  and `go test -race ./...`. `govulncheck` found no known vulnerabilities in the source
  or the release executables.
- Automated tests cover the handoff folder content, each rejection condition of a
  continue, prompt quoting in sh, bash, and zsh, and per-run replay. A real-server test
  continues a worktree session, restarts the server, and continues it again.
- A compiled release smoke check uses a temporary instance to verify version reporting,
  the embedded UI and license notices, read-only SQL, and clean shutdown.
- Both archives match `checksums.txt`. Each archive contains the executable, `LICENSE`,
  and `THIRD_PARTY_NOTICES.txt`. Both executables report Go 1.27.3 and
  `CGO_ENABLED=0`.
- A manual upgrade check used a temporary instance and a real interactive shell. A
  v0.0.4 build started a Shell session, sent a command with Send, and saved a draft. The
  0.0.5 `server restart` then replaced that server.
- After the upgrade, the recorded events and the session record were unchanged. The
  stopped session showed its saved final screen and draft. **Continue in new terminal**
  started a second terminal in the same workspace with the same draft.
- The handoff folder for that session listed the v0.0.4 terminal with tool Shell. It
  had the full transcript and the sent message with status Sent.
- Before the merge of #13, a live check continued one session six times with Codex CLI
  0.160.0 and Claude Code 2.1.312. Both agents read the handoff folder and summarized
  the earlier terminals. This release build was not checked again with a real agent.
- Publication requires tests and native release smoke checks on both Apple Silicon and
  Intel runners. The Intel executable was not run locally. Safari and Firefox were not
  tested.
