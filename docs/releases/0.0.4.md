BonBon 0.0.4 lets you resize and hide the sidebar. Terminal views now keep up to 10,000
scrollback rows instead of 2,000. New size limits keep large or colorful output from
closing a view. The database format and the protocol do not change.

## Included

- Drag the divider on the right edge of the sidebar to change its width. Or focus the
  divider and use Left/Right to change the width in 20-pixel steps. Home and End go to
  the limits. A double-click restores the default width.
- The sidebar width stays from 240 to 480 pixels. The main area keeps at least 400
  pixels, so a small window lowers the maximum. Below a window width of 950 pixels, the
  default width is now 240 pixels instead of 225 pixels.
- Click the panel button at the left of the session title to hide or show the sidebar.
  Command-B does the same. Ctrl+B stays available to terminal programs such as tmux. The
  terminal gets the free space.
- The sidebar width and visibility stay with the browser tab across session switches. A
  reload resets them. Other tabs are not affected.
- Terminal views keep up to 10,000 normal-screen scrollback rows instead of 2,000. A
  view keeps the newest rows that fit in 8 MiB of rendered text. Plain output keeps all
  10,000 rows. Output with many colors or styles keeps fewer rows.
- A frame now carries at most 11 MiB of rendered text, so it stays below the 16 MiB
  WebSocket message limit. Before this release, a first frame with a color change on
  almost every cell could go over that limit, and the server closed the view. Now a full
  frame always includes the visible screen and omits the oldest rows that do not fit.
- A view that is narrower than the terminal keeps a cache of its cropped rows. Each
  frame renders only new rows. At 10,000 rows, the cost of each frame decreased from
  24–62 ms to less than 1 ms. Output capture now waits much less for this work.

## Upgrade from v0.0.3

```sh
bonbon update
```

The update replaces the executable while existing servers and sessions continue. When
ready, run:

```sh
bonbon server restart
bonbon ui
```

Restart ends active sessions. Then use the new UI at its new URL. Close BonBon tabs from
v0.0.3.

This release keeps SQLite format 6 and protocol `bonbon/17`, so a v0.0.3 database needs
no migration. Databases from v0.0.1 (formats 3–5) still upgrade automatically at
startup.

Database downgrades are not supported. Saved final screens from earlier releases stay
valid in this release. But v0.0.3 cannot show the final screen of a session that this
release saved with more than 2,000 scrollback rows.

## Install

Install with one command:

```sh
curl -fsSL https://github.com/gyson/bonbon/releases/latest/download/install.sh | sh
```

The installer selects Apple Silicon or Intel. It verifies SHA-256 and the executable
version. It installs to `~/.local/bin`. If needed, add that directory to PATH. Use
installer `--version 0.0.4` to select this release explicitly. Then run
`bonbon server start` and `bonbon ui`.

## Scope and limits

- macOS Apple Silicon and Intel archives, plus `install.sh` and `checksums.txt`.
  Installed binaries need neither Go, Node.js, nor GitHub CLI.
- Built with Go 1.27.3 and `CGO_ENABLED=0`. Archives and the standalone executable
  include the project license and dependency notices.
- Production data remains in `~/.bonbon`, separate from `~/.bonbon-dev`. This release
  uses SQLite format 6 and protocol `bonbon/17`.
- BonBon does not save the sidebar width and visibility. A reload or a server restart
  resets them.
- The server's terminal buffer grows with the row limit. At 10,000 rows, it uses about
  19 MiB for each session at 160 columns and about 61 MiB at 512 columns. The 8 MiB
  limit applies only to rendered rows.
- Rows older than the view limit remain only in the SQLite recording. Use `bonbon query`
  to read them. BonBon has no terminal search. The browser's find command sees only the
  visible rows.
- A frame still fails if the visible screen alone is larger than the frame limit. This
  needs a screen of about 512 × 256 cells with unusual content.
- Native agent resume, conversation forks, imports, and backup/restore remain
  unavailable. Terminal recordings do not restore a process or hidden model state.
- Linux and Windows packages, background updates, and Apple Developer ID
  signing/notarization are not included.

## Validation

- Local checks with Go 1.27.3: `make test`, `make check`, `make web-check` (32 tests),
  and `go test -race ./...`. `govulncheck` found no known vulnerabilities in the source
  or the release executables.
- Automated tests cover the sidebar width limits, the scrollback size limit, frames at
  the message limit, and the row cache for narrow views.
- A compiled release smoke check uses a temporary instance to verify version reporting,
  the embedded UI and license notices, read-only SQL, and clean shutdown.
- Both archives match `checksums.txt`. Each archive contains the executable, `LICENSE`,
  and `THIRD_PARTY_NOTICES.txt`. Both executables report Go 1.27.3 and
  `CGO_ENABLED=0`.
- A manual upgrade check used a temporary instance and a real interactive shell. A
  v0.0.3 build started a Shell session and sent `seq 1 3000` with Send. The 0.0.4
  `server restart` then replaced that server.
- After the upgrade, the recorded events and the session record were unchanged. The
  final screen that v0.0.3 saved opened correctly, and **Sent messages** showed the
  message as **Sent**. The sidebar button hid and showed the sidebar.
- A new 0.0.4 Shell session ran `seq 1 15000`. The view kept exactly 10,000 scrollback
  rows, from row 4987. After the session stopped and the server restarted, the saved
  final screen opened with the same rows.
- Publication requires tests and native release smoke checks on both Apple Silicon and
  Intel runners. The Intel executable was not run locally. Safari and Firefox were not
  tested. This release does not claim a new end-to-end run with a real agent CLI.
